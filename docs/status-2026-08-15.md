# ডেডলাইন স্ট্যাটাস — ২০২৬-০৮-১৫

তৈরি হয়েছে: 2026-08-15, প্রায় দুপুর ১টা (Bangladesh time) — মালিকের ২টার ডেডলাইনের আগে শেষ চেক হিসেবে।

## সংক্ষেপে

আজ শিডিউল করা চারটা কাজের জন্য মোট **৫টা Pull Request (PR)** খোলা পাওয়া গেছে — চারটা না, পাঁচটা। কারণ
নিচে ব্যাখ্যা করা আছে (একই কাজ দুইবার হয়ে গেছে)। প্রতিটা branch checkout করে `npm install` এবং
`npm run build` চালিয়ে যাচাই করা হয়েছে — **সবগুলোই বিল্ড পাস করে।** কোনো কিছু merge করা হয়নি, `main`-এ
কিছু push করা হয়নি — শুধু যাচাই করা হয়েছে, যেমনটা নির্দেশ ছিল।

**⚠️ সবচেয়ে গুরুত্বপূর্ণ সতর্কতা — আগে এটা পড়ুন:** PR #3 আর PR #5 — দুটোই **একই কাজ** (বটকে বাংলাদেশের
আসল সময় শেখানো) আলাদাভাবে করে ফেলেছে, সম্ভবত দুইটা শিডিউল করা agent ভুলবশত একই কাজে বসে গিয়েছিল। দুটোই
`src/lib/bot.js` ফাইলের একই অংশ বদলেছে। **দুটোই একসাথে merge করলে সরাসরি conflict হবে** (আমি সরাসরি
পরীক্ষা করে দেখেছি — `git merge-tree` দিয়ে)। যেকোনো **একটা** merge করুন, অন্যটা বন্ধ (close) করে দিন।
নিচে বিস্তারিত আছে কোনটা রাখা ভালো।

## যেভাবে বিল্ড যাচাই করা হয়েছে

এই sandbox-এ কোনো আসল Supabase/Gemini credential নেই (`.env.local` নেই), তাই প্রথমবার `npm run build`
চালাতে গেলে সবগুলো branch-ই (এমনকি অপরিবর্তিত `main`-ও) একই এরর দিয়ে ফেল করে: `Error: supabaseUrl is
required`। এটা কোডের বাগ না — sandbox-এ credential না থাকার কারণে। তাই `main` branch নিজেও একইভাবে
ফেল করে কিনা যাচাই করে নিশ্চিত হওয়ার পর, placeholder (ভুয়া, কাজ-না-করা) মান দিয়ে আবার বিল্ড চালানো
হয়েছে — শুধু বিল্ড/কম্পাইল ঠিকমতো হচ্ছে কিনা দেখার জন্য, আসল ডাটাবেজ-সংযোগ পরীক্ষা করার জন্য না। এই
পদ্ধতিতে ৬টা বিল্ডই (৫টা PR + `main`) **সফল** হয়েছে।
